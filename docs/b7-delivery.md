| 场景 | 验证内容 |
|---|---|

默认 3 人成局包含发起人。因此浏览器脚本用 A 的真实 API 会话发布，B/C/D 独立浏览器会话回应；并非只让两个账号凑成 3 人。新增 API 超时用例也验证 A+D 的 2 人需求及双方读取一致状态。

## 一键复跑

先准备独占、空白 TEST 数据库，设置 DATABASE_URL、APP_ENV=test、JWT_SECRET、CORS_ORIGIN 后，运行 npm run db:migrate、npm run db:seed。不要使用生产库、共享联调库或 postgres/template 数据库。脚本不会自动 reset 数据库，也不会刷新过期种子时间；过期时应准备新的隔离库。

```powershell
$env:APP_ENV='test'
$env:DATABASE_URL='<独占测试数据库连接串>'
$env:JWT_SECRET='<至少32位的专用测试密钥>'
$env:CORS_ORIGIN='http://localhost:4173'
$env:B7_ISOLATED_DB='1'
npm run test:b7
```

完整浏览器验收另需已安装的 Microsoft Edge 与外部 Playwright：

```powershell
$env:P0_PLAYWRIGHT_PATH='<Playwright index.mjs 绝对路径>'
npm run test:b7-browser
```

浏览器模式使用自动分配的本机端口，构建时注入对应 API 地址及 CORS；不需要手动启动服务。默认浏览器渠道 msedge，可用 B5_BROWSER_CHANNEL 修改。报告及截图在 .artifacts/b7，已加入 .gitignore；报告只保存阶段名、通过与否、耗时和起止时间，不保存 JWT、密码或数据库连接串。每轮报告留存并更新 latest.json。失败停止后续步骤并退出 1；自身启动的 API/H5 在 finally 关闭。

顺序为：库预检 → 全仓 lint → 服务端编译 → H5 类型检查 → B7 安全门禁单元 → Schema 测试 → 服务端测试 → B5/B6/需求中心单元 → SSR 构建/渲染 → EdgeOne 构建 → 可选多账号浏览器验收。共享种子夹具文件串行运行，测试内部的 Promise.all 并发检查不变。

## 失败记录与修复

| 失败/复现步骤 | 原因与处理 |
|---|---|
| 在隔离库提前设置邀请到期，同时发送接受和重复超时扫描 | 确认现有事务/状态机能收敛到 EXPIRED 和唯一递补；新增自动化回归，不修改生产状态规则 |
| 浏览器原生计时器轮询一次后停止 | B5 已修复 clearTimeout 原生调用绑定；浏览器跨账号自动递补继续覆盖 |
| 旧 seed 库匹配返回 409 | 种子报名截止已过；重新准备隔离库，不放宽生产截止校验；B7 前置检测明确提示 |
| 多个集成文件共享库时 seed 学校数量失败 | 测试文件临时增加学校/角色干扰；B6 已改文件级串行，保留用例内部并发 |
| 复组需求与原需求同名导致浏览器按钮定位不唯一 | B6 已改为需求 ID 定位，不改真实标题或业务数据 |
| B7 首轮一键验收在 lint 阶段失败 | 脚本使用独立三元表达式触发 no-unused-expressions；改为显式 if/else，验证失败即停止的报告机制有效 |
| 中止 /me/invitations 网络请求 | 明确失败提示与重新读取恢复，数据库不产生虚构成功；浏览器脚本保留此验收 |

## 验收边界

自动化使用真实 PostgreSQL、真实 API、真实独立登录会话及移动视口；为避免等待 24 小时/多天，仅在隔离测试库调整测试邀请/活动时间，再调用真实任务。正式 H5 无此强制转换入口。

实体双手机、生产部署及双方签字仍属于共同验收，不以移动视口模拟冒充。现场验收可由 A 手机发布数模、B 手机回应、C 另一独立会话补齐默认 3 人，然后检查同一 sessionId、时间窗口内签到、完成后评价和复组；运营账号回查轨迹与指标。TEST 数据不得进入正式指标。
